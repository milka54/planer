## 4. Как собирать

```powershell
# Окружение (важно!)
$env:ANDROID_HOME = "D:\dev\android-sdk"
$env:ANDROID_SDK_ROOT = "D:\dev\android-sdk"
$env:GRADLE_USER_HOME = "D:\dev\gradle-home"
$env:JAVA_HOME = "D:\dev\Android Studio\jbr"
$env:FLUTTER_STORAGE_BASE_URL = "https://storage.googleapis.com"
cd D:\projects\Planer

# Android
flutter build apk --release
# → build\app\outputs\flutter-apk\app-release.apk

# Windows
flutter build windows --release
# → build\windows\x64\runner\Release\planer.exe

# Установщик ПК (нужен Inno Setup 7: C:\Program Files\Inno Setup 7\ISCC.exe)
& "C:\Program Files\Inno Setup 7\ISCC.exe" installer\planer-setup.iss
Copy-Item installer\planer-setup.exe dist\planer-setup.exe -Force

# Проверки
flutter analyze lib     # должно быть 0 ошибок
flutter test -j 1       # 12 тестов (см. §7)
```

**Тонкости сборки:**
- Если `pub get` зависает → `flutter pub get --offline`
- Если Gradle падает на скачивании с `storage.flutter-io.cn` → переключить на `storage.googleapis.com`
- APK подписывается автоматически ключом из `android/key.properties`

- Подпись SHA-256: `8c793838…ddee71` (совпадает с keystore-info)

### GitHub Releases (Windows)
Инструкция: `dist/GITHUB-RELEASE-GUIDE.md`
1. Собрать `planer-setup.exe` + обновить `dist/version.json` (версия + что нового)
2. GitHub → репозиторий → **Releases** (правая боковая панель!) → Create new release
3. Тег `v1.X.Y`, загрузить `planer-setup.exe` и `version.json`
4. Имена файлов в релизе **всегда постоянные** (`planer-setup.exe`, `version.json`)
   — приложение качает по `releases/latest/download/…`, ссылка не меняется

## 6. Что осталось / известные ограничения

- [ ] **Скриншоты RuStore** — пользователь обновит сам
- [ ] **SmartScreen** при установке на ПК — предупреждение из-за отсутствия кодовой подписи.
  Решение: SignPath.io (бесплатно для open-source) или сертификат. Блок подписи
  уже готов в `installer/build-release.ps1` (signtool) — раскомментировать.
- [ ] **Фоновые уведомления чата при закрытом приложении** — не работают (таймер Flutter
  живёт только при запущенном приложении). Нужен FCM или WorkManager.
- [ ] Ежегодный повтор напоминаний срабатывает только при открытии приложения.
- [ ] Gradle предупреждает о Kotlin Gradle Plugin — когда-нибудь мигрировать.

## 9. Ключевые архитектурные решения

- **Firebase-проект:** `my-notes-71034`. Личные данные: `users/{uid}/{notes|sections|reminders|reminder_sections|joined_spaces}`.
- **Общие пространства:** `family_spaces/{id}` + `members/notes/messages/invites/deletions`;
  приглашения по email — `mailboxes/{email}/invites`; по ссылке — `join_codes/{token}`.
- **Windows без Firebase SDK** → REST-слой `lib/data/firebase_rest.dart` (тот же проект).
- **Вступление в группу — только по приглашению или коду-ссылке** (правила Firestore);
  удалять задачи/пространства может только создатель; участник может выйти.
- **Удаление задач в общих пространствах — tombstones** (`deletions/{noteId}` с `wasDone`),
  чтобы все участники видели «X удалил(а) задачу».
- **Приглашение по ссылке = копирование + вставка** (не share-меню), ссылка `planer://join/<token>`
  открывает приложение (deep link).
- **Проверка обновлений ПК** — манифест `version.json` по стабильному URL `releases/latest/download/`.
- **ID объектов** = таймстамп + счётчик (не чистый `DateTime.now()` — коллизии на Windows).
